The agent inspects the runtime it is running in, then grows new fibers on that tree.

Because everything is a plugin, self-modification is not a special interpreter. It is the same mount, inject, and dispose algebra as boot — pointed at model-written code.

Three correctness problems, not a party trick

Handing the model the live tree is interesting. Doing it without wrecking the process required three answers:

  1. Malformed tool schemas must fail at registration, not at the next prompt assembly.
  2. Model-written code must call service APIs it has never seen. Guessed signatures cost blind probing. The inspect tool therefore serves a generated catalog, not a remembered table.
  3. Everything the model mounts must be fully disposable — by the model, and by ordinary plugin unload — or a long session accretes orphaned listeners.

pnpm run demo:cordis boots examples/web-cordis. The shipped verbs split define and run so a human sees a card and starts it. Older note language said cordis_mount / cordis_unmount; the idea is the same.

The model-facing verbs

ToolContract
cordis_inspectLive services, fibers, tools, temporary packages, plus generated API, event, and client-slot catalogs. Exact name returns original JSDoc.
cordis_defineSyntax-check a host half and/or a browser half. Mint dyn-n. Nothing runs until start.
cordis_runEvaluate the host half in node:vm. A browser half is an answerable round trip: a page must allow or decline. Re-running a live package re-delivers it to a reloaded page instead of failing.
cordis_stopDispose to quiescence. The definition survives.
cordis_undefineForget the definition.

Temporary packages live under an internal cordis-dynamic group and are session-scoped: visible and controllable only in the session that defined them, while still able to affect other sessions in the same process. They create no file, change no cordis.yml, do not survive restart, and have no promote path. Keeping an experiment means implementing a normal plugin through the regular workflow. Cross-mount composition is ordinary provide / inject.

A façade, not a jail

Mount code runs as an async-function body in a fresh vm realm. Globals are small: a tagged console, harness.defineTool / registerTool, encoding primitives, and throwing traps over require, timers, and fetch that name the Cordis alternative. process and Buffer stay undefined so a typeof probe stays inert.

The mounted plugin receives a whitelist context, not a raw Context. Service reads require a declared inject. ctx.tools.get exposes only the schema view, so mounted code cannot bypass ToolRuntime.execute. Dual-realm instanceof recognizes both host and vm objects. Output schemas are rebuilt in the host realm so the canonical-output contract still holds.

The catalog is generated and freshness-gated

Inspect intersects compile-time Typert / docs catalogs with the live service store. Broad reports stay compact. Exact-name reports pay for full JSDoc. verify-cordis-api regenerates in memory and fails on any diff, so a signature edit cannot ship without updating what the model reads. Client slot catalogs come from every SlotMap merge and slots.register site — the model can sit UI into real seats.

Bash-equivalent, and they will not let you forget it

The vm hides Node globals and steers file, network, and timer access toward Cordis services. The capabilities those services expose — ctx.shell, ctx.fs, ctx.web — reach the real runtime and may affect other sessions in the process. Host-realm helpers still allow escape. This is an opt-in development tool, not a security boundary and not a product default.

Model-visible means logged still holds without a new event type. Mount and run are tool/call / tool/result pairs. A changed tool set is the next full request/header. Resume rehydrates conversation history and never recreates temporary plugins.
