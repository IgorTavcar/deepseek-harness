Continuation is policy. The loop only admits another turn.

A goal is not Ralph. Ralph is not a workflow script. A workflow is not a subagent. Plan mode is not a sandbox. A webhook is not a scheduler. Each of these is a plugin on agent/*, the session log, ctx.subagents, or ctx.webhookRuntime.

Goals stay in the session

A goal is a durable completion objective attached to an existing session: revisioned phase active / paused / blocked / complete, plus a goal-round cap. blocked keeps a policy code and explanation. A goal is state, not a scheduler and not a separate conversation. The session log remains the source of truth.

A goal round is one continuation cycle admitted for the current goal, materialized as one goal-sourced turn. Unrelated human turns in the same session do not consume the cap. Activation is process-local, armed or disarmed, and deliberately absent from durable replay. Resume and fork require a later human-authorized resume through /goal or the model tool before automatic work. That is how a restored session does not immediately run away.

Ralph is a fresh-agent loop

Ralph is a model-facing tool policy composed from workflow and subagent primitives. One foreground run toward an immutable objective. Each round is a fresh child session that receives no parent or prior-child conversation seed. The shared workspace plus one bounded RalphRoundReport — status, summary, evidence, next steps, blocker text — carry cross-round state. Default cap is large (256 rounds). The provider must declare inheritsParentContext: false.

This is the opposite of a goal. A goal wants the conversation as memory. Ralph wants a clean context and a dirty workspace. Mixing them produces a child that inherits a parent prompt it cannot see the point of, or a same-session loop that pretends it started over.

Workflows are scripts, not the loop

ctx.workflowEngine runs model-authored orchestration in a worker thread. Isolation from the host event loop is not a security boundary. The general workflow tool and the fixed Ralph consumer both start runs whose agent() calls fan out through ctx.subagents. There is no named-provider registry: one engine per context, as with bash. The shipped ptc preset disables the general workflow tool so PTC does not grow a second orchestration surface; Ralph keeps the engine.

Delegation is a seam

Providers: spawn-in-process, fork-in-process, ACP, Codex, Claude Code, out-of-process dsh via the TypeScript SDK. The service also owns optional Activation-based continuation. tool-subagent selects one-shot or continuable delegation. tool-subagent-control delivers follow-ups. Background children register with ctx.jobs; job_* collects or stops them.

Lineage is data — parentSession, durable delegationDepth, runtime subagentDepth — and never affects visibility. Scoped registrations do not inherit down to children. If a child needs a tool, give it the tool.

Plan is logged collaboration, not confinement

ctx.planMode folds plan/mode from the log, flushes user selections at turn boundaries, renders deployment-owned guidance, and registers /plan. Sandbox mode and approval policy do not read that boolean. Switching a permission preset writes one permission/preset event through to both knob events. The model can be in plan collaboration with workspace-write already on, or in full access with plan still active. Those combinations are allowed because the axes are independent.

A webhook is a birth, not a supervisor

A signed delivery hits a provider adapter, then a trusted rule. The rule returns null or one Workspace-backed Session request. The runtime stores no delivery record and does not wait for the Agent. A 202 means verified dispatch. Repeated deliveries may create another Session. Ordinary persistence owns later work.

Agent Teams are not the default catalog

Experimental ctx.agentTeams layers a durable roster, mailbox, and task board over continuable children. The implicit Lead is the ordinary root Session. Teammates are named continuable children, not a new loop. The default tool catalog does not change. Released products must not depend on packages/experimental/.
