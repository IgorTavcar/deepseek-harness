The log is the conversation. Messages are a fold.

Fork, resume, transcripts, telemetry, titles, compaction, and the next model request all derive from one append-only stream. A second operative “conversation client” is the bug this design exists to make unrepresentable.

Model-visible means logged

Anything that reaches a model request must be reconstructable from the session log and the immutable content-addressed attachments it names. The checkable consequence: anyone holding the log, those objects, and the pinned code version reconstructs every loop request. New model-visible input requires a new SessionEventMap member and a renderer from the log.

This is MiniCode's stateful conversation client, with the event log as the client. Prefix-cache stability is a corollary, not a cache manager: an append-only log projected by a per-node pure function yields requests that are append-extensions of their predecessors whenever the header is unchanged.

Divergence between “what the model saw” and “what we stored” is structurally unrepresentable. That is the whole point.

Surface versus tape

Every event is on the tape. Only some events are on the surface that deriveMessages() walks. Surface-eligible types may carry surfaceOp: 'append' or { op: 'replace', start, end }:

  • user/message — prompts, steering, injects, runtime-context snapshots, additional tool contexts.
  • assistant/message — assembled assistant. Empty content is skipped in derivation and kept on the tape for usage and sourceEventSeqs.
  • tool/result — the single model-facing outcome of a call.

Not surface: turn/*, step/*, assistant/chunk, tool/call, request/header, request/context, inbox splices, todo/write, Code Mode tool/code-dispatch*. Chunks exist so a UI can replay token streams. The assembled message cites them. Compaction does not mutate history: it appends a replace that shadows a range. Those nodes drop out of derivation. The cache extends incrementally and rebuilds when replaceGeneration bumps.

The header is the non-history envelope

request/header snapshots call config, rendered system prompt, and tool schemas. The first loop instance writes reason initial, a later instance writes resume, an in-instance change writes change. foldRequestHeader selects the latest snapshot. request/context records provider, model, and context window when the route or window changes.

Adapter-materialized defaults are marked. Before the next waterfall the loop strips marked fields so the current exact route rematerializes its own maxTokens and reasoning effort. Unmarked explicit settings persist across steps and route changes. A route with no adapter preserves the proposal so an llm/stream listener can short-circuit it; unhandled dispatch still fails NO_ADAPTER.

Refuse loud, never gut silently

SESSION_FORMAT_VERSION is a monotonic integer, currently pinned at 0. Pre-release: backends reject old on-disk formats, there is no compatibility promise, and vocabulary growth does not bump the version. Bump only for structural changes.

A SessionEventMap member is required-on-read by default. A build that does not know the type refuses the log unless the event carries ignorable: true. Default-required is inconvenient when someone forgets the marker. Default-ignorable would resume a gutted session. The design prefers inconvenience.

A newer-than-reader log throws SessionFormatUnsupportedError naming the direction. SQLite persistence uses its own monotonic SCHEMA_VERSION.

Persistence, fork, repair

Persistence is a seam. JSONL and SQLite backends persist the same SessionEvent vocabulary. Apps choose a backend at composition time. Write-behind listens to session/event. session/flush is an explicit observation barrier.

ctx.sessions.fork(source, boundary?, childSessionId?) copies a completed-turn prefix. Seed events and session metadata are validated and snapshotted because they cross the durable boundary. Resume loads through ctx.sessionPersistence, then runs unpublished setup against a fresh scope. Turn numbering continues. Temporary self-mounted plugins do not: they are process memory.

Crash repair and interrupted-turn markers belong to the persistence backends, not the loop. The session companion invariant checks monotonic seq, turn/step enclosure, and same-step tool call/result pairing.

Everything else is a projection

Titles fold the log through a sole ctx.sessionTitle provider, with a deterministic fallback. Session query offers exact reads, traces, filters, and a SQLite full-text backend. Projections register fold units; a cache checkpoints them so listings never load full logs. Telemetry captures, redacts, and hands records to one backend. Message feedback lives beside the log, not in it.

Goals, plan mode, permission presets, and todos all append their own event types and fold them back. The conversation vocabulary does not grow a special case for each of them.
