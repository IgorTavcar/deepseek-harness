Call the model. Run the tools. Repeat. Log everything the model can see.

The only package with concrete loop logic is dsh-agent-loop. Its internal driver, ReactLoopAgent, implements the public Agent contract. Extension plugins depend on dsh-agent, never on this package, so the driver stays swappable.

Turn, step, round

A session is an append-only SessionEvent log. A turn is one admission of work: it opens before the first input is claimed and closes once nothing is owed. A step is one model request plus the tools that request caused. A turn contains zero or more steps. A round belongs to an outer policy — a goal round or a Ralph attempt — and is not a loop counter.

This split is load-bearing. Compaction, retry, and cancellation close or open turns. Steering continues a turn. Injected context waits for a later claim. The log records a rejected first claim as a durable turn that spent no step, so the attempt is not a ghost.

One inbox, three verbs

Work enters through send(message, target, wakeup). The aliases are fixed presets:

APITargetWakes the driver?Meaning
followupnext-turnyesOne ordinary prompt, its own turn.
steernext-stepyesNearest step; idle drivers open a turn.
injectnext-stepnoContext for the next admitted request. Waits.

Claim is the ownership transfer. At a turn boundary the driver drains every next-step item and then takes one next-turn message. Between steps it drains next-step only. Claimed messages never return. agent/pre-step then returns reject or enter(messages, startsRequestSeries?). A rewrite to empty on the first claim still closes the turn. Wrapping listeners spread the decision so a series flag survives.

Every mutation publishes agent/inbox/spliced before the live arrays change. Insertions emit agent/inbox/inserted. Ordinary removals are cancellations. Claim is a pure deletion plus agent/inbox/claimed { message, turn }.

The machine

Step through the driver. The highlighted row is the current phase. Continuation after tools is data: if tools ran and did not conclude the turn, the next step happens even with an empty inbox.

01Wake while idle. Status becomes running. One abort controller owns the activity.
02Append turn/start before claiming anything.
03Claim: all next-step, plus one next-turn at the boundary.
04Assemble prompt sections and tool schemas. Optionally mint a runtime-context snapshot.
05agent/pre-step waterfall: reject, or enter the authoritative messages. Optional startsRequestSeries.
06On enter: step/start, append each entered message as user/message.
07Derive history. agent/request then prepareCall. Log request/header.
08llm/stream → assistant/chunk* → one assistant/message.
09Classify tool calls. Exclusive barriers. Bounded rolling pool for parallel-safe bodies.
10step/end. Tools owed another request? Claim next-step only and loop.
11Natural stop and empty next-step: serial agent/turn-stopping. Re-read the inbox. Steer keeps the turn open.
12turn/end. If next-turn work remains, a new controller and another turn. Else idle.

The model never sees an invented array

There is no parallel conversation client. After the entered user messages are appended, the driver calls session.deriveMessages(). That fold walks surface nodes: user/message, non-empty assistant/message, and tool/result. Chunks, tool calls, inbox splices, PTC sub-dispatches, and lifecycle events stay off the provider transcript.

Empty assistant messages are still logged. A max-tokens finish needs a durable usage anchor. deriveMessages skips empty content so the provider transcript stays well-formed.

The optional dsh-agent-loop/invariant companion rebuilds the frozen request from a fresh Session at llm/stream and compares messages plus folded header fields. The live cache cannot vouch for itself.

Tool scheduling is not policy

executeToolCalls in tool-calls.ts owns order and overlap. Classification is unary and fail-closed: only an exact true from isConcurrencySafe(args) is parallel. Missing, hidden, throwing, or non-true classifiers are exclusive. The scheduler reclassifies immediately before start.

Only dispatch and the tool body overlap. Logging tool/call, tools/pre-execute, guards, tools/post-execute, finalizeContent, and tool/result stay in model order. A head-of-line cursor commits results so parallel bodies that finish early cannot leapfrog the transcript.

The rolling pool defaults to maxParallelToolCalls: 10, writable from Settings for the next group. Exclusive calls drain the pool, run alone, and hold the barrier through commit. Abort stops new starts, drains started work, and writes synthetic tool/call + ABORTED_BEFORE_DISPATCH pairs for skipped calls so replay remains a legal pairing. A scheduler crash drains bodies and does not fabricate results.

A waterfall listener that returns without next() short-circuits. That is the design for a policy that owns the decision, and a trap for an observer who forgets to delegate.

What the loop refuses to own

Outside

Permission, sandbox, plan-mode deny/ask, tool timeouts, result rewrite, compaction, model retry, persistence, subagents, jobs, persona, tool bodies, UI cards, turn budgets.

Inside

Phase machine, claim, turn/step enclosure, request freeze and header log, stream assembly, tool scheduling, synthetic abort pairing, cancel/wake latch, factory create/resume rollback.

Plugin exceptions end the current turn, not the loop. Cancellation is cooperative. Waking input that lands after abort and before idle is latched and replayed, except a disposed cancel, which never latches. whenIdle() follows replacement drivers, not a snapshot of the first activity it saw.
