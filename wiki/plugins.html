seq 0003 vendor/cordis · spatiotemporal composability

A plugin is a fiber. A registration is an effect. Unload is the same algebra as dispose.

Cordis is the vendored kernel. Its paper is A Programming Paradigm for Spatiotemporal Composability. DeepSeek Harness takes that claim literally: the product is the tree you boot, and every contribution is bound to the lifetime of the fiber that installed it.

Five ideas

A plugin implements Service

A function with inject and apply(ctx), or a Service subclass. There is no second kind of first-class module.

A context is a service repository

Plugins find ctx.tools, ctx.llm, ctx.sessions by key. They do not import a concrete loop or a concrete bash.

inject is load order

A plugin that names required services waits until those services exist. Boot sequencing is a dependency graph, not a handwritten list of requires.

Typed events, four modes

Declaration merging extends SessionEventMap and live maps. Dispatch is emit, waterfall, parallel, or serial. The mode is part of the public contract, tagged @mode so generated catalogs can check call sites.

Registrations are reversible effects

Prompt sections, tool schemas, adapters, providers, and listeners go through ctx.effect() or ctx.on(). A registry register() returns the disposer. HMR, preset unmount, agent disposal, and process shutdown unwind the same way. If teardown order matters, keep the related work in one effect.

Waterfalls are around-middleware

A waterfall listener receives (...args, next). Call next() to delegate the possibly wrapped result. Return without it to short-circuit. Values travel through next()'s return. Cooperative listeners mutate a shared decision object and then delegate. A listener can also replace the result so downstream only sees the replacement.

prepend: true is for work that must run before ordinary registrations. For single-decision events, short-circuiting is the point: a policy that owns the decision skips next(); an observer that only annotates must not.

The same unwind at every scale

Unload a plugin and every effect it registered disappears. Dispose an agent and its scoped world, tools, listeners, and session detach to quiescence. Provider unload of AgentLoop stops and drains every live handle it made. Create and resume are one rollback-covered transaction: unpublished setup, then enter, then session/created then agent/created. A setup rejection never publishes either id.

The vendored loader is hardened for this product: transactional Include (import a candidate, await settle, restore on failure), serialized child-tree mutation so HMR cannot deadlock, and lazy !!js interpolation of config and disabled only after inject. Other entry metadata stays literal. Conditional composition uses overlays, not clever YAML.

Profiles are a patch algebra

A running dsh starts from an empty entry list. Layers apply in order: each bundle in the profile, then the profile's cordis.patch.yml, then the home-level patch, then any --patch overlay. A patch targets a row by id and replaces its whole config, or inserts new rows.

A profile lives in the Harness home. It lists the bundles it stacks, holds out-of-tree plugins, and keeps the user's patch. Shipped templates: web, headless, sdk, sdk-minimal, acp. A bundle is an npm package with dsh.bundle pointing at a patch file. dsh-base is the shared first layer of web, headless, sdk, and acp: adapters, tools, persistence, sandbox, approval, settings, credentials, telemetry. dsh-web-app adds the browser application. dsh-headless adds a one-shot runner with no server. dsh-sdk-app and dsh-acp-app add those servers. sdk-minimal does not apply base: one bundle owns its complete explicit tree. Custom profiles and shipped web default to live patch reload; the one-shot and stdio profiles apply layers once at startup.

dsh --profile web --dump-config

That command prints the tree applyEntryPatches would mount — the same function boot uses. Any printed row can be replaced by a patch of your own.

Per-session presets

A preset is a directory with agent.cordis.yml mounted under the unpublished setup(agentCtx) window as a Cordis include subtree. The host plane stays process-global: registries, persistence, providers, the web server. The agent plane is what this session contributes. A preset row that publishes into the root service realm is rejected at mount. Resume rebuilds the composition recorded by agent-preset/selected, not today's default.

Isolation is the default. Sharing an expensive singleton is an explicit isolate realm, not an accident of import graphs.

The agent is a registration scope

createScope(ctx, key) mints a tagged context. Registrations through agent.ctx are visible to that agent and disposed with it. Two facts, one mechanism. Shadowing is most-specific-wins: a scoped tool or prompt section replaces its global twin for that agent alone. Restrictions filter the global tool set by intersection; scope-local tools merge afterwards. A filtered-away global is absent from the prompt and refuses execution, the same as a missing name.

Parent chain: registrations inherit down, events admit up. scopeTarget brands the dispatch thisArg so a bare subject is a compile error. Scopes route trusted same-process plugins. They are not sandboxes and not authority boundaries. That non-goal is written down so nobody “fixes” it into a security feature.

Standing rules that make the tree survivable

  • New behavior attaches to a documented extension point. Changing the loop updates docs/architecture.md.
  • Extension plugins depend on Service Definitions, never concrete providers.
  • Defaulting is an explicit resolve(request): Spec step. Hidden ?? default inside run() is forbidden. The shell request/spec split is the template.
  • Deployment tunables are validated Config fields from cordis.yml. A DEFAULT_* constant is not configurability.
  • Misconfiguration fails loud at load when self-contained, otherwise at the earliest resolvable point.
  • Opaque ids are branded. ToolExecutionToken is a branded Symbol so it cannot leak onto the wire.
  • Trust TypeScript at typed same-process boundaries. Validate at parser, config, model/tool JSON, durable, worker, process, and wire edges.
