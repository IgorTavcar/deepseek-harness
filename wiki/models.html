seq 0007 deepseek-official · deepseek-v4-flash

The product is built against DeepSeek V4. Everyone else arrives through a dormant second adapter.

Default conversation route: provider: deepseek-official, model: deepseek-v4-flash. The catalog also advertises deepseek-v4-pro. Both default to a 1,000,000-token context window and a 256,000-token output cap. Older names such as deepseek-chat and deepseek-reasoner survive only as test fixtures.

The native catalog is advisory. Unlisted ids still pass through as the wire model string, so a company-hosted reasoner does not require a code change. listModels('deepseek-official') exists for the Web picker and ACP editors. Context capacity comes from the entry or from defaultContextWindow, not from treating the picker as authoritative.

Images are refused on the official chat-completions route. A custom pi-ai model is text-only until its input list says otherwise.

Both can be mounted at once because the route names differ. A private DeepSeek-dialect gateway on an unrecognized URL must set compat.thinkingFormat: deepseek or pi-ai will speak OpenAI at it.

pi-ai's installed catalog is how Anthropic, OpenAI, Kimi, xAI, Groq, and hand-declared OpenAI-compatible gateways appear. Bedrock, Vertex, Azure, and Codex need their native credentials; an API-key field does not configure them. OAuth-only catalog routes such as openai-codex are withheld from the configurable-provider directory because this adapter has no login flow.

Reasoning is a content block, not a side channel

Harness effort ids are opaque branded strings. Native DeepSeek advertises off, high, max on every pass-through model unless the deployment locks thinking. Omitted config defaults to high. thinking: disabled publishes only off and refuses high/max at load and at request time.

Adapter-owned off serializes as thinking: { type: 'disabled' } and never as reasoning_effort: 'off'. high and max enable thinking and send the official top-level reasoning_effort. Session-title requests force thinking off so a 64-token title budget is not eaten by chain-of-thought. Compaction keeps conversation thinking defaults and only adds x-deepseek-harness-compact: 1.

Official thinking-plus-tools requires a passback rule: on assistant history that carried tool calls, concatenate reasoning into reasoning_content. On tool-free turns, drop it. The first SSE thinking chunk is an empty string and must not open a block. Assistant content is "", never null — gateways reject null, and a reasoning-only greeting would 400 and brick the session.

pi-ai exposes whatever getSupportedThinkingLevels returns, including minimal, low, medium, xhigh. A model with no reasoning metadata exposes no reasoning field at all: offering off would be a no-op that can lie if the provider thinks by default. Reasoning tokens, when DeepSeek reports them, are a subdivision of output, not a fifth usage bucket. pi-ai folds them into output.

Four layers hit the wire in this order

  1. ctx.agentDefaultModel — composition default, settings-writable, including optional effort. Headless and Host share this owner.
  2. Session-local ModelSelection — a pick writes provider, model, and effort through agent/request. A session that already logged a request keeps its own model. Switching to a text-only model is refused if the log already holds images.
  3. AgentOptions seed the loop proposal. agent/request may fill a missing pair. After the waterfall, missing provider or model throws.
  4. The adapter. Native pass-through versus pi-ai's closed catalog.

Connection facts are not frozen at load. Both adapters re-read settings and credentials once per operation. An in-flight stream keeps the facts it started with. Keys are write-only; settings store references; values live in $DSH_HOME/.credentials.yaml. First-run onboarding is “browse models, store the key, prompt again,” with no restart.

Surprising wire facts

  • Streaming only. Usage is deferred until [DONE] so it always precedes finish.
  • DeepSeek prompt_tokens includes cache hits. Harness usage is disjoint: input minus cache-read. No cache-write metric.
  • SSE comments rearm the idle watchdog and never become chunks or log events.
  • Empty completed stop becomes EMPTY_RESPONSE and is retried by default policy.
  • Unknown finish_reasons such as content_filter become error finishes.
  • Native requests carry harness User-Agent, anonymous user id, optional session id, and the compact header when relevant.
  • Web search is a third DeepSeek HTTP dialect and does not go through ctx.llm.
  • An image admitted to the log before a failed vision request stays there. Recovery is another vision model, a fork, or a new session.

Retry and tokens live outside the adapter

One stream() call makes one provider request. SDK retries are forced to zero. dsh-llm-retry listens to agent/request-error and executes the policy captured on the route. Default normal: two retries for empty, rate-limit, server, timeout, transport; backoff 500ms–10s with jitter; DeepSeek Retry-After wins. Mode always retries every model-request failure after downstream recovery. Each wait logs non-surface llm/retry. The loop closes the failed turn and opens a new numbered turn over the same history.

ctx.tokenMeter folds the durable log. Heuristic is 4 characters per token plus structure. Capacity comes from resolveModelInfo().context. Compaction scales thresholds against the routed model's window. Provider usage is reused only when the latest successful call's envelope still matches.
